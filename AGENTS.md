# MouseLFP model and optimization autoresearch

Read README.md and program.md before changing the research workflow.

## Research scope

- Protocol version 5 permits candidate edits to `meta_learning/frontend.py`, `models/cnn.py`, and the explicitly editable optimization fields in `configs/meta.json`. Both frontend and CNN architecture, widths/depths, kernels, transforms, normalization, nonlinearities, and initialization are research variables. The fixed input is centered/resampled waveforms `(N, 28672)`; the frontend declares positive `(channels, time)` in `WaveformFrontend.output_shape`, and the candidate CNN consumes that interface and emits two class logits.
- Editable configuration fields are exactly `outer_steps`, `inner_epochs`, `inner_lr`, `inner_weight_decay`, `classifier_dropout`, `outer_lr`, `outer_weight_decay`, `support_loss_weight`, `batch_size`, `frontend_batch_size`, `label_smoothing`, and `gradient_clip`. All other resolved configuration fields remain locked. Current values, including 50 outer steps and 40 inner epochs, are the initial baseline; changing permission does not change these values or start training. Each candidate must declare and finish its own budget before promotion; report its complete configuration and runtime.
- The user explicitly designated test Days 12/13 as a development set for frontend search. Promote candidates by minimum equal-mouse-mean test log loss at each run's query/valid-selected checkpoint. Report threshold-0.5 accuracy alongside loss. These results are search/development metrics, not an untouched final generalization estimate.
- Inside each candidate, preserve query/valid checkpoint selection, full hypergradients, and support-only fitting. Test labels never supply gradients, CNN fitting, BatchNorm statistics, or within-run checkpoint selection. Only cross-candidate promotion reads test scores.
- `protocol.lock.json` binds fixed trainer/normalization code, noneditable configuration fields, sample/crop policy, dependencies, launchers, and this workflow. Architecture and allowed optimization changes belong to immutable candidate snapshots, not the session identity. Do not refresh the lock to admit candidate changes. Any further infrastructure change requires a separately reviewed protocol and a fresh session/baseline. Version-3 and version-4 sessions remain preserved and use their saved source/runtime; version 5 starts a fresh study and baseline.
- Frontend features must be deterministic, sample-local, stateless across calls, differentiable with respect to their waveform and learned parameters, finite for silence, and independent of frontend chunk size. No cross-sample statistics, mutable fitted statistics, or dropout inside the frontend. Neither editable model may access external weights, recording metadata, labels, files/data, or training/evaluation code. The CNN may use configured dropout and support-fitted BatchNorm through the locked `models/normalization.py`; native PyTorch BatchNorm is unsupported by the differentiable solver. CNN evaluation must be deterministic and never mutate saved/reference statistics.
- Keep generated caches, logs, checkpoints, all old research sessions, and the agent-maintained five-column `results.tsv` outside version control. Use a dedicated `autoresearch/<tag>` branch: commit each candidate before training, retain improvements, and reset failed/discarded candidate commits to their saved parent after logging. Preserve unrelated changes; never use `git clean` to remove research artifacts.

## Fixed meta-learning controls

- Once the user starts an autoresearch study, continue the agent experiment loop until the user interrupts, honoring any explicit user limit. Each training/evaluation job remains bounded by its configured budget. Building code or documentation does not start a study.
- Run one candidate at a time. After it finishes, the agent reads the result or failure logs, records its keep/discard/crash decision, completes the Git action, and uses that feedback to choose the next hypothesis. Wait for running tool sessions to finish. Do not precommit, queue, batch-launch, or edit future candidates while the current experiment runs.
- Preserve private recordings, source annotations, historical experiment artifacts, and unrelated user changes.
- Keep train Days 0-7, validation Days 8/11, and test Days 12/13. Modeled mice are X1/X2/X4/X9/X10/X14/X15.
- Use one fixed task per mouse: all training Days 0-7 are support, validation Days `query_validation_days` (currently Days 8/11) are query, and test Days 12/13 are eval. `selection_validation_days` is currently null, so checkpoint selection reuses query loss; an explicit non-null list must be disjoint from query days and supplies selection only. Do not construct rolling episodes or subsample dates. Query-day labels supervise outer frontend updates; selection-day labels never supply gradients; test is inference only within training, and supplies the cross-candidate development score.
- Every outer step includes each configured mouse exactly once. Weight its gradient by its eligible query-event count divided by the total query-event count, then update once after all tasks; never subsample mice or draw them with replacement. Count unique positive query events before crop expansion or per-class caps; matched negatives do not add events. Average meta query losses within each represented event, then across events. Crop counts do not change event weights.
- Fixed preprocessing is per-window mean removal, resampling to 256 Hz, and zero padding. Put every additional transform inside the editable frontend; never cache learned or spectral candidate features before it. The initial candidate is the retained RMS/asinh waveform ResNet with overlapping downsampling and the current three-block CNN. Both are baselines, not architectural constraints. `frontend_batch_size` controls frontend chunks independently of CNN `batch_size`; changing only the frontend chunk size must preserve crop RNG draws and the CNN schedule. Changing CNN batch size is an explicit optimization candidate. Do not load historical trained CNN weights.
- `augment_random_crop` replaces meta-training support and query windows, and per-mouse fitting support windows when support crops are enabled, with random real crops: positives anywhere inside their event's 7-3 minute interval, negatives from all eligible seizure-free intervals of the same mouse and day (`sample_pipeline.safe_regions`), sampled uniformly over all legal 112 s start positions. Every crop must keep its label definition and stay within its recording day. Draw crop positions from the checkpointed episode RNG. Per-mouse fits share the meta inner fits' support policy exactly (same `support_crops`, `inner_epochs`, and optimizer), drawing crops from a fixed per-mouse seed so checkpoints are reproducible. Never crop selection, query-refit evaluation, or test windows. `random_crop_scope` selects support, query, or both; `query_crops` averages K independent query crops per event and class. `support_crops` gives each event K positive crops and K matched negative crops within one inner fit, independent of its fixed-window count. Negative counts are per-event budgets; positions are independent of matched fixed negative rows. Weight safe intervals by their legal-start counts, preserve the configured recording scope, and cache long intervals with bounded preparation memory. Plan crops over the full support before batching, so each event is counted once. Optional per-class caps limit generated crop examples. `inner_epochs` is not rescaled; with four fixed windows per event and class, K crops give about K/4 times the optimizer steps of a fixed-window fit.
- Do not fit dataset or task normalization statistics. Normalization inside the candidate may use only the current waveform and learned frontend parameters. The baseline uses sample-local RMS and GroupNorm; alternatives are allowed within that boundary.
- The only meta-parameters are the shared preprocessing frontend. Train a task-local CNN from reproducible unlearned starting weights for that candidate; CNN architecture/initialization may differ across candidates. Never meta-learn CNN initialization or carry adapted classifiers between tasks. Preserve the frontend-to-inner-training-to-query gradient path.
- Train the inner CNN for complete shuffled epochs, preserving weights and optimizer state within a task. `inner_shuffle_seed` remains locked; fixed shuffles must not advance the run's RNG streams. The solver implementations remain plain inner SGD without momentum and outer AdamW; their exposed rates/weight decay and classifier dropout are editable optimization parameters. Final per-mouse fitting uses the same inner solver and candidate parameters. Do not add optimizer selectors or moment tensors to the inner fit. `inner_weight_decay` retains its defined L2 pull toward detached unlearned reference weights after loss-gradient clipping, identically in meta inner and per-mouse fits.
- Train every inner CNN for exactly the candidate's configured complete epochs, with no early stopping or best-epoch rollback. Epoch/outer-step budgets may change only as explicit cross-candidate optimization hypotheses, never in response to intermediate metrics within a run. The initial JSON uses 40 inner epochs rather than the Config default of 50, and 50 outer steps rather than 100; retain these baseline values until an explicit candidate changes them. Intermediate support metrics are diagnostic only. Preserve diagnostic frequency, final support-only BatchNorm recalibration, full eligible support/query tasks, and every data-role restriction.
- The per-mouse outer objective is `query_loss + support_loss_weight * support_loss_after_last_update`. The support term averages all samples used in the inner fit after its final update and support-only BatchNorm recalibration, in eval mode without dropout or statistics updates. Use configured label smoothing for both terms. Preserve direct frontend gradients and full hypergradients through every inner update and support statistics. The coefficient is editable, finite, and nonnegative; default 0.1 and zero restores query-only training. Apply the existing query-event mouse weights to the entire objective. Log query loss, final-support loss, weighted support term, and total separately. Query/valid checkpoint selection and development-test ranking remain unchanged.
- Use RNG-preserving activation checkpointing for long inner trajectories; do not silently truncate their hypergradients. Final per-mouse CNN fitting uses the same fixed epoch solver and budget.
- Final per-mouse fitting freezes the shared frontend and trains a fresh CNN from a reproducible unlearned reference.
- Restore normal CNN BatchNorm behavior: support training uses batch statistics and updates task-local running means/variances; query/test use eval mode and the fitted support statistics. Reset statistics with each fresh CNN and save the fitted statistics with adapted checkpoints. Checkpoint/replay must include the task-local BatchNorm state and preserve the full outer gradient through its support-only EMA updates. Never let query inference or backward replay mutate saved/reference statistics. After each fit, recalibrate BatchNorm statistics exactly on the full support with the final weights (differentiably in the meta path); never use query data for them.
- Select checkpoints by minimum mouse-mean log loss on the selection days after matched support-only CNN fitting (query days only when `selection_validation_days` is null, which selects the most query-fitted frontend). Report accuracy at threshold 0.5. Test metrics never select checkpoints within a training run; they rank completed frontend candidates only. Record sample counts, class ratios, window settings, source fingerprints, configuration, runtime, and selected checkpoints.
- Query loss and the final-support regularizer supply the outer gradient; selection days only select checkpoints. Query and selection never supply inner CNN updates or fitted normalization statistics. The outer optimizer is AdamW with decoupled `outer_weight_decay` on frontend weight matrices only (not biases, normalization parameters,).
- Score test Days 12/13 every eval_every steps (also the final step), alongside query metrics, without fitting or gradients. The separate test command replays selected checkpoints without training. Never use test metrics for within-run checkpoint selection.
- Source preparation verifies recording identities and annotation alignment. Describe signal-quality audits by their actual coverage.
- Keep dependencies stable in a comparison. Preserve source snapshots and completed/interrupted run records; resume only compatible checkpoints.
- Accept only current configuration and artifact fields. Do not add historical aliases, schema migrations, identity-scale parameters, or alternative training paths. Replay commands name one role: query, valid, or test.
- Preserve caller CPU/CUDA RNG streams during seeded initialization; instantiate each CNN once.
- Use English in code, comments, configurations, logs, and project documentation.

Primary research entry points: research.py, run_research.sh, program.md, and protocol.lock.json. Fixed training entry points remain prepare.py, train.py, evaluate.py, run_meta.sh, and the meta_learning package.
