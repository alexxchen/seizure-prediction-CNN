# MouseLFP cross-day meta-learning

Read README.md before changing the training pipeline.

- Work on explicit, finite training and evaluation jobs. Building code or documentation does not authorize long training runs.
- Preserve private recordings, source annotations, historical experiment artifacts, and unrelated user changes.
- Keep train Days 0-7, validation Days 8/11, and test Days 12/13. Modeled mice are X1/X2/X4/X9/X10/X14/X15.
- Use one fixed task per mouse: all training Days 0-7 are support, validation Days `query_validation_days` (currently Days 8/11) are query, and test Days 12/13 are eval. `selection_validation_days` is currently null, so checkpoint selection reuses query loss; an explicit non-null list must be disjoint from query days and supplies selection only. Do not construct rolling episodes or subsample dates. Query-day labels supervise outer frontend updates; selection-day labels never supply gradients; test is inference only.
- Every outer step includes each configured mouse exactly once. Weight its gradient by its eligible query-event count divided by the total query-event count, then update once after all tasks; never subsample mice or draw them with replacement. Count unique positive query events before crop expansion or per-class caps; matched negatives do not add events. Average meta query losses within each represented event, then across events. Crop counts do not change event weights.
- On `meta-learning/waveform-conv-frontend`, do not precompute STFT or other spectral features. Fixed preprocessing is limited to per-window mean removal, resampling to 256 Hz, and zero padding. Apply sample-local RMS normalization inside the frontend instead of a fixed unit multiplier. The frontend is a single generic, randomly initialized pre-activation 1-D ResNet (strided Conv1d downsampling, GroupNorm/GELU residual blocks with zero-initialized last convs) whose head emits a (channels, time) feature sequence (currently 64 × 256, about 131k parameters). Avoid hand-designed stages (filterbanks, modulus/log, fixed pooling, residual base maps). The task CNN is one-dimensional (Conv1d over time, channels as features); shape the reference CNN from the attached frontend's output. Do not reshape feature channels into an artificial 2-D image. Initialize without advancing caller RNG streams. Frontend features must depend only on their own sample. `frontend_batch_size` (default 32) controls frontend window chunks independently of CNN `batch_size`; changing it must preserve crop RNG draws and the CNN training schedule. Do not load historical trained CNN weights.
- `augment_random_crop` replaces meta-training support and query windows, and per-mouse fitting support windows when support crops are enabled, with random real crops: positives anywhere inside their event's 7-3 minute interval, negatives from all eligible seizure-free intervals of the same mouse and day (`sample_pipeline.safe_regions`), sampled uniformly over all legal 112 s start positions. Every crop must keep its label definition and stay within its recording day. Draw crop positions from the checkpointed episode RNG. Per-mouse fits share the meta inner fits' support policy exactly (same `support_crops`, `inner_epochs`, and optimizer), drawing crops from a fixed per-mouse seed so checkpoints are reproducible. Never crop selection, query-refit evaluation, or test windows. `random_crop_scope` selects support, query, or both; `query_crops` averages K independent query crops per event and class. `support_crops` gives each event K positive crops and K matched negative crops within one inner fit, independent of its fixed-window count. Negative counts are per-event budgets; positions are independent of matched fixed negative rows. Weight safe intervals by their legal-start counts, preserve the configured recording scope, and cache long intervals with bounded preparation memory. Plan crops over the full support before batching, so each event is counted once. Optional per-class caps limit generated crop examples. `inner_epochs` is not rescaled; with four fixed windows per event and class, K crops give about K/4 times the optimizer steps of a fixed-window fit.
- Do not fit dataset or task normalization statistics before the frontend. The frontend applies per-window RMS normalization, then GroupNorm on residual-branch inputs. Its residual stream carries the RMS-normalized waveform. Do not add an amplitude bypass or gain augmentation. If fitted normalization is introduced later, support statistics come from Days 0-7 only and are reused for query and eval.
- The only meta-parameters are the shared preprocessing frontend. Train a task-local CNN from fixed unlearned starting weights; never meta-learn CNN initialization or carry adapted classifiers between tasks. Preserve the frontend-to-inner-training-to-query gradient path.
- Train the inner CNN for complete shuffled epochs, preserving weights and optimizer state within a task. `inner_shuffle_seed` (null by default) may fix each task's window order and minibatch shuffles across outer steps for a deterministic meta objective; fixed shuffles must not advance the run's RNG streams. Use plain SGD (configurable inner_lr, default 0.01; no momentum) and classifier dropout 0; final per-mouse fitting uses the same inner optimizer. Inner and final per-mouse fits use plain SGD directly, with no optimizer selector. Do not allocate or checkpoint momentum or Adam moment tensors. Keep the outer AdamW optimizer unchanged. `inner_weight_decay` adds L2 toward the detached unlearned reference weights after loss-gradient clipping, identically in meta inner and per-mouse fits.
- Train every inner CNN for exactly the configured complete epochs, with no early stopping or best-epoch rollback. Preserve the current `configs/meta.json` budget; the JSON currently uses 40 epochs, overriding the Config default of 50. Document explicit JSON overrides of Config defaults and preserve user-selected training budgets. Support loss and accuracy are diagnostic only. With `inner_log_every=0`, measure support only at initialization and the final epoch; positive values also measure the first epoch and each configured interval. Always complete every training epoch and retain final support BatchNorm recalibration. Default episodes use all eligible support/query windows. Query data must never update the inner CNN directly or change its epoch budget; test data must never affect training or selection. Smaller fixed budgets are permitted for explicit smoke checks and tests.
- Use RNG-preserving activation checkpointing for long inner trajectories; do not silently truncate their hypergradients. Final per-mouse CNN fitting uses the same fixed epoch solver and budget.
- Final per-mouse fitting freezes the shared frontend and trains a fresh CNN from a reproducible unlearned reference.
- Restore normal CNN BatchNorm behavior: support training uses batch statistics and updates task-local running means/variances; query/test use eval mode and the fitted support statistics. Reset statistics with each fresh CNN and save the fitted statistics with adapted checkpoints. Checkpoint/replay must include the task-local BatchNorm state and preserve the full outer gradient through its support-only EMA updates. Never let query inference or backward replay mutate saved/reference statistics. After each fit, recalibrate BatchNorm statistics exactly on the full support with the final weights (differentiably in the meta path); never use query data for them.
- Select checkpoints by minimum mouse-mean log loss on the selection days after matched support-only CNN fitting (query days only when `selection_validation_days` is null, which selects the most query-fitted frontend). Report accuracy at threshold 0.5. Test metrics never select checkpoints. Record sample counts, class ratios, window settings, source fingerprints, configuration, runtime, and selected checkpoints.
- Query days supply the outer gradient; selection days only select checkpoints. Neither supplies inner CNN updates or fitted normalization statistics. The outer optimizer is AdamW with decoupled `outer_weight_decay` on frontend weight matrices only (not biases, normalization parameters,).
- Score test Days 12/13 every eval_every steps (also the final step), alongside query metrics, without fitting or gradients. The separate test command replays selected checkpoints without training. Never use test metrics for checkpoint selection.
- Source preparation verifies recording identities and annotation alignment. Describe signal-quality audits by their actual coverage.
- Keep dependencies stable in a comparison. Preserve source snapshots and completed/interrupted run records; resume only compatible checkpoints.
- Validate temporal isolation, hypergradients, checkpoint resumption, and inference behavior with tests. Use a separate short run for real-data smoke checks.
- Accept only current configuration and artifact fields. Do not add historical aliases, schema migrations, identity-scale parameters, or alternative training paths. Replay commands name one role: query, valid, or test.
- Preserve caller CPU/CUDA RNG streams during seeded initialization; instantiate each CNN once.
- Use English in code, comments, configurations, logs, and project documentation.

Primary entry points: prepare.py, train.py, evaluate.py, run_meta.sh, and the meta_learning package.
