# MouseLFP cross-day meta-learning

Read README.md before changing the training pipeline.

- Work on explicit, finite training and evaluation jobs. Building code or documentation does not authorize long training runs.
- Preserve private recordings, source annotations, historical experiment artifacts, and unrelated user changes.
- Keep train Days 0-7, validation Days 8/11, and test Days 12/13. Modeled mice are X1/X2/X4/X9/X10/X14/X15.
- Use one fixed task per mouse: all training Days 0-7 are support, validation Days `query_validation_days` (currently Day 8) are query, the disjoint `selection_validation_days` (currently Day 11) select checkpoints, and test Days 12/13 are eval. Do not construct rolling episodes or subsample dates. Query-day labels supervise outer frontend updates; selection-day labels never supply gradients; test is inference only.
- Every outer step includes each configured mouse exactly once (all seven in the full configuration). Average their gradients and update once after all tasks; never subsample mice or draw them with replacement. Apply the same schedule to the pooled control.
- On `meta-learning/neural-stft-frontend`, connect fixed log1p STFT magnitudes to the task CNN through a generic convolution + MLP residual frontend: a strided Conv2d/GELU trunk and a per-time-bin LayerNorm/MLP whose zero-initialized output is added to the average-pooled log-STFT map. Avoid hand-designed learned stages. Feed the CNN the native 56 × 40 grid without frequency resizing. The initial representation must equal pure log-STFT, without advancing caller RNG streams. Frontend features must depend only on their own sample. Do not load historical trained CNN weights.
- Do not fit dataset or task normalization statistics before the frontend. Sample-local normalization inside the learned branch (LayerNorm) is allowed; the residual base path preserves absolute amplitude. If fitted normalization is introduced later, support statistics come from Days 0-7 only and are reused for query and eval.
- The only meta-parameters are the shared preprocessing frontend. Train a task-local CNN from fixed unlearned starting weights; never meta-learn CNN initialization or carry adapted classifiers between tasks. Preserve the frontend-to-inner-training-to-query gradient path.
- Pure log-STFT is an independent `algorithm="log_stft"` option. Never run a startup baseline for meta or pooled jobs. The baseline fits each mouse's CNN once on Days 0-7, scores query Days 8/11 and eval Days 12/13, and saves replayable checkpoints/predictions and a completion report in its own run directory. It performs no outer updates regardless of the outer-step budget. Reuse a completed compatible standalone baseline on resume.
- Train the inner CNN for complete shuffled epochs, preserving weights and optimizer state within a task. `inner_shuffle_seed` (null by default) may fix each task's window order and minibatch shuffles across outer steps for a deterministic meta objective; fixed shuffles must not advance the run's RNG streams. Default to plain SGD (learning rate 0.001, no momentum; momentum 0.9 made the meta objective chaotic) and classifier dropout 0; final per-mouse fitting uses the same inner optimizer. Apply the same dropout configuration to the pooled control. If Adam is explicitly selected, preserve its bias-correction step counts across replay segments and keep zero-variance hypergradients finite.
- Train every inner CNN for exactly the configured complete epochs, with no early stopping or best-epoch rollback. Preserve the current `configs/meta.json` budget; the Config default remains 50. Support loss and accuracy are diagnostic only. Default episodes use all eligible support/query windows. Query data must never update the inner CNN directly or change its epoch budget; test data must never affect training or selection. Smaller fixed budgets are permitted for explicit smoke checks and tests.
- Use RNG-preserving activation checkpointing for long inner trajectories; do not silently truncate their hypergradients. Final per-mouse CNN fitting uses the same fixed epoch solver and budget.
- Final per-mouse fitting freezes the shared frontend and trains a fresh CNN from a reproducible unlearned reference. The pooled control may train an auxiliary CNN to learn its representation, but must discard that CNN before final per-mouse fitting.
- Restore normal CNN BatchNorm behavior: support training uses batch statistics and updates task-local running means/variances; query/test use eval mode and the fitted support statistics. Reset statistics with each fresh CNN and save the fitted statistics with adapted checkpoints. Pooled training uses normal training-mode BatchNorm on its supervised examples. Checkpoint/replay must include the task-local BatchNorm state and preserve the full outer gradient through its support-only EMA updates. Never let query inference or backward replay mutate saved/reference statistics. After each fit, recalibrate BatchNorm statistics exactly on the full support with the final weights (differentiably in the meta path); never use query data for them.
- Compare against ordinary pooled supervised training with the same architecture, episode examples, normalization, outer-step budget, and personalization budget. Report extra meta-training compute separately.
- Select checkpoints by minimum mouse-mean log loss on the selection days after matched support-only CNN fitting (query days only when `selection_validation_days` is null, which selects the most query-fitted frontend). Report accuracy at threshold 0.5. Test metrics never select checkpoints. Record sample counts, class ratios, window settings, source fingerprints, configuration, runtime, and selected checkpoints.
- Query days supply the outer gradient; selection days only select checkpoints. Neither supplies inner CNN updates or fitted normalization statistics. The outer optimizer is AdamW with decoupled `outer_weight_decay` on frontend weight matrices only (not biases, LayerNorm, or an auxiliary CNN). The pooled control may use train plus validation labels for its supervised representation objective.
- Score test Days 12/13 once for the standalone log-STFT algorithm, or every eval_every steps (also the final step) for meta/pooled, alongside query metrics, without fitting or gradients. The separate test command replays selected checkpoints without training. Never use test metrics for checkpoint selection.
- Source preparation verifies recording identities and annotation alignment. Describe signal-quality audits by their actual coverage.
- Keep dependencies stable in a comparison. Preserve source snapshots and completed/interrupted run records; resume only compatible checkpoints.
- Validate temporal isolation, hypergradients, checkpoint resumption, and inference behavior with tests. Use a separate short run for real-data smoke checks.
- Use English in code, comments, configurations, logs, and project documentation.

Primary entry points: prepare.py, train.py, evaluate.py, run_meta.sh, and the meta_learning package.
