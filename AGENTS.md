# MouseLFP cross-day meta-learning

Read README.md before changing the training pipeline.

- Work on explicit, finite training and evaluation jobs. Building code or documentation does not authorize long training runs.
- Preserve private recordings, source annotations, historical experiment artifacts, and unrelated user changes.
- Keep train Days 0-7, validation Days 8/11, and test Days 12/13. Modeled mice are X1/X2/X4/X9/X10/X14/X15.
- Use one fixed task per mouse: all training Days 0-7 are support, all validation Days 8/11 are query, and test Days 12/13 are eval. Do not construct rolling episodes or subsample dates. Validation query labels supervise outer frontend updates; test is inference only.
- Every outer step includes each configured mouse exactly once (all seven in the full configuration). Average their gradients and update once after all tasks; never subsample mice or draw them with replacement. Apply the same schedule to the pooled control.
- On `meta-learning/neural-stft-frontend`, connect fixed STFT magnitudes to the task CNN with a shared residual Conv2d/GELU network, smooth log1p compression, average pooling, and bilinear resizing. Preserve the full temporal map; do not reintroduce hard medians, rank selection, log flooring, or two constant time blocks. Initialize a small nonzero residual without advancing caller RNG streams. Do not load historical trained CNN weights.
- Preserve absolute amplitude with identity normalization (scale=1) in episodes, personalization, and inference. If fitted normalization is introduced later, episode statistics must use support only and personalization statistics Days 0-7 only, reused for validation and test.
- The only meta-parameters are the shared preprocessing frontend. Train a task-local CNN from fixed unlearned starting weights; never meta-learn CNN initialization or carry adapted classifiers between tasks. Preserve the frontend-to-inner-training-to-query gradient path.
- Before the first outer update, run a parameter-free log1p-STFT baseline with the neural residual bypassed. Fit fresh per-mouse CNNs on Days 0-7 with the current fitting budget, score query Days 8/11 and eval Days 12/13 with the same trained CNN, and print per-mouse and mean metrics. Save baseline checkpoints/predictions and reuse a completed compatible baseline on resume. Preserve the neural initialization and training RNG state; keep baseline artifacts separate from learned-frontend selection.
- Train the inner CNN for complete shuffled epochs, preserving weights and optimizer state within a task. Default to SGD with momentum 0.9 and classifier dropout 0; final per-mouse fitting uses the same inner optimizer. Apply the same dropout configuration to the pooled control. If Adam is explicitly selected, preserve its bias-correction step counts across replay segments and keep zero-variance hypergradients finite.
- Train every inner CNN for exactly the configured complete epochs, with no early stopping or best-epoch rollback. Preserve the current `configs/meta.json` budget; the Config default remains 50. Support loss and accuracy are diagnostic only. Default episodes use all eligible support/query windows. Query data must never update the inner CNN directly or change its epoch budget; test data must never affect training or selection. Smaller fixed budgets are permitted for explicit smoke checks and tests.
- Use RNG-preserving activation checkpointing for long inner trajectories; do not silently truncate their hypergradients. Final per-mouse CNN fitting uses the same fixed epoch solver and budget.
- Final per-mouse fitting freezes the shared frontend and trains a fresh CNN from a reproducible unlearned reference. The pooled control may train an auxiliary CNN to learn its representation, but must discard that CNN before final per-mouse fitting.
- Restore normal CNN BatchNorm behavior: support training uses batch statistics and updates task-local running means/variances; query/test use eval mode and the fitted support statistics. Reset statistics with each fresh CNN and save the fitted statistics with adapted checkpoints. Pooled training uses normal training-mode BatchNorm on its supervised examples. Checkpoint/replay must include the task-local BatchNorm state and preserve the full outer gradient through its support-only EMA updates. Never let query inference or backward replay mutate saved/reference statistics.
- Compare against ordinary pooled supervised training with the same architecture, episode examples, normalization, outer-step budget, and personalization budget. Report extra meta-training compute separately.
- Select checkpoints by minimum seven-mouse mean validation-query log loss after matched support-only CNN fitting. Report accuracy at threshold 0.5. Test metrics never select checkpoints. Record sample counts, class ratios, window settings, source fingerprints, configuration, runtime, and selected checkpoints.
- Days 8/11 supply the outer query gradient and select checkpoints. They do not supply inner CNN updates or fitted normalization statistics. The pooled control may use train plus validation labels for its supervised representation objective.
- Score test Days 12/13 at step 0 and every eval_every steps (also the final step), alongside query metrics, without fitting or gradients. The separate test command replays selected checkpoints without training. Never use test metrics for checkpoint selection.
- Source preparation verifies recording identities and annotation alignment. Describe signal-quality audits by their actual coverage.
- Keep dependencies stable in a comparison. Preserve source snapshots and completed/interrupted run records; resume only compatible checkpoints.
- Validate temporal isolation, hypergradients, checkpoint resumption, and inference behavior with tests. Use a separate short run for real-data smoke checks.
- Use English in code, comments, configurations, logs, and project documentation.

Primary entry points: prepare.py, train.py, evaluate.py, run_meta.sh, and the meta_learning package.
