# MouseLFP model and optimization autoresearch

Read README.md and program.md before changing the research workflow.

## Research scope

- Protocol version 13 permits candidate edits to `meta_learning/frontend.py`, `models/cnn.py`, and the explicitly editable optimization fields in `configs/meta.json`. Both frontend and CNN architecture, widths/depths, kernels, transforms, normalization, nonlinearities, and initialization are research variables. The fixed input is centered/resampled waveforms `(N, 28672)`; the frontend declares positive `(channels, time)` in `WaveformFrontend.output_shape`, and the candidate CNN consumes that interface and emits two class logits.
- Editable configuration fields are exactly `outer_steps`, `inner_epochs`, `inner_lr`, `inner_weight_decay`, `classifier_dropout`, `outer_lr`, `outer_weight_decay`, `support_loss_weight`, `batch_size`, `frontend_batch_size`, `label_smoothing`, `gradient_clip`, and `support_pool_crops`. All other resolved configuration fields remain locked. The user-selected version-13 baseline uses 200 outer steps and 40 inner epochs; changing permission does not change these values or start training. Each candidate must declare and finish its own budget before promotion; report its complete configuration and runtime.
- The user explicitly designated test Days 12/13 as a development set for frontend search. Promote candidates by minimum equal-mouse-mean test log loss at each run's query/valid-selected checkpoint. Report threshold-0.5 accuracy alongside loss. These results are search/development metrics, not an untouched final generalization estimate.
- Inside each candidate, preserve query/valid checkpoint selection, full hypergradients, and support-only fitting. Test labels never supply gradients, CNN fitting, BatchNorm statistics, or within-run checkpoint selection. Only cross-candidate promotion reads test scores.
- `protocol.lock.json` binds fixed trainer/normalization code, noneditable configuration fields, sample/crop policy, dependencies, launchers, and this workflow. Architecture and allowed optimization changes belong to immutable candidate snapshots, not the session identity. Do not refresh the lock to admit candidate changes. Any further infrastructure change requires a separately reviewed protocol and a fresh session/baseline. Version-3 through version-12 sessions remain preserved and use their saved source/runtime. The user-requested version-7 protocol keeps PyTorch-compatible defaults and zero-centered inner L2, and removes final BatchNorm recalibration; it requires a fresh session and baseline.
- Frontend features must be deterministic, sample-local, stateless across calls, differentiable with respect to their waveform and learned parameters, finite for silence, and independent of frontend chunk size. No cross-sample statistics, mutable fitted statistics, or dropout inside the frontend. Neither editable model may access external weights, recording metadata, labels, files/data, or training/evaluation code. The CNN may use configured dropout and support-fitted BatchNorm through the locked `models/normalization.py`; native PyTorch BatchNorm is unsupported by the differentiable solver. CNN evaluation must be deterministic and never mutate saved/reference statistics.
- Keep generated caches, logs, checkpoints, all old research sessions, and the agent-maintained five-column `results.tsv` outside version control. Use a dedicated `autoresearch/<tag>` branch: commit each candidate before training, retain improvements, and reset failed/discarded candidate commits to their saved parent after logging. Preserve unrelated changes; never use `git clean` to remove research artifacts.

## Fixed meta-learning controls

- Once the user starts an autoresearch study, continue the agent experiment loop until the user interrupts, honoring any explicit user limit. Each training/evaluation job remains bounded by its configured budget. Building code or documentation does not start a study.
- Run one candidate at a time. After it finishes, the agent reads the result or failure logs, records its keep/discard/crash decision, completes the Git action, and uses that feedback to choose the next hypothesis. Wait for running tool sessions to finish. Do not precommit, queue, batch-launch, or edit future candidates while the current experiment runs.
- Preserve private recordings, source annotations, historical experiment artifacts, and unrelated user changes.
- Keep train Days 0-7, validation Days 8/11, and test Days 12/13. Modeled mice are X1/X2/X4/X9/X10/X14/X15.
- Use one fixed task per mouse: all training Days 0-7 are support, validation Days `query_validation_days` (currently Days 8/11) are query, and test Days 12/13 are eval. `selection_validation_days` is currently null, so checkpoint selection reuses query loss; an explicit non-null list must be disjoint from query days and supplies selection only. Do not construct rolling episodes or subsample dates. Query-day labels supervise outer frontend updates; selection-day labels never supply gradients; test is inference only within training, and supplies the cross-candidate development score.
- Every outer step includes each configured mouse exactly once. Weight its gradient by its eligible query-event count divided by the total query-event count, then update once after all tasks; never subsample mice or draw them with replacement. Count unique positive query events before crop expansion or per-class caps; matched negatives do not add events. Average meta query losses within each represented event, then across events. Crop counts do not change event weights.
- Fixed preprocessing is per-window mean removal, resampling to 256 Hz, and zero padding. Put every additional transform inside the editable frontend; never cache learned or spectral candidate features before it. The initial candidate is the retained RMS/asinh waveform ResNet with overlapping downsampling and the current three-block CNN. Both are baselines, not architectural constraints. `frontend_batch_size` controls frontend chunks independently of CNN `batch_size`; changing only the frontend chunk size must preserve crop RNG draws and the CNN schedule. Changing CNN batch size is an explicit optimization candidate. Do not load historical trained CNN weights.
- `augment_random_crop` replaces meta-training support and query windows, and per-mouse fitting support windows when support crops are enabled, with random real crops: positives anywhere inside their event's 7-3 minute interval, negatives from all eligible seizure-free intervals of the same mouse and day (`sample_pipeline.safe_regions`), sampled uniformly over all legal 112 s start positions. Every crop must keep its label definition and stay within its recording day. Draw crop positions from the checkpointed episode RNG. Per-mouse fits share the meta inner fits' support policy exactly (same `support_pool_crops`, `support_crops`, `inner_epochs`, and optimizer), drawing crops from a fixed per-mouse seed so checkpoints are reproducible. Never crop selection, query-refit evaluation, or test windows. `random_crop_scope` selects support, query, or both; `query_crops` averages K independent query crops per event and class. `support_crops` gives each event K positive crops and K matched negative crops within each inner epoch, independent of its fixed-window count. Negative counts are per-event budgets; positions are independent of matched fixed negative rows. Weight safe intervals by their legal-start counts, preserve the configured recording scope, and cache long intervals with bounded preparation memory. Plan crops over the full support before batching, so each event is counted once. Optional per-class caps limit generated crop examples. `inner_epochs` is not rescaled; with four fixed windows per event and class, K crops give about K/4 times the optimizer steps of a fixed-window fit.
- Protocol version 9 resamples support positions before every meta inner epoch and matched per-mouse SGD refit epoch. Advance the checkpointed crop RNG; keep CNN weights and support BN EMA continuous, with the configured full shuffled epochs and unchanged optimizer update count. Query is drawn once per outer task. Replay restores private crop RNG states and complete CNN/BN segment boundaries, reconstructing one epoch's features at a time with full frontend/update/EMA hypergradients and no caller RNG consumption. Final fitted-support loss averages all actual fitted draws across all epochs at final weights/statistics; intermediate epoch metrics use the current draw. This user-requested infrastructure change requires a fresh v9 session/baseline for future training; preserve all v8 and earlier artifacts. Editing does not start training.
- Protocol version 10 implements the user-requested support4 comparison: lock support_crops=4 and retain v9 per-epoch resampling, full replay hypergradients, continuous CNN/BN state, and the all-fitted-draw support objective. Keep dropout=0, query_crops=64 and the declared 200 outer/40 inner budget. Start a fresh session/baseline and preserve all v9 records. Set the session watchdog to 172800 seconds before launch; keep it fixed during the session. This failure limit does not change optimizer budgets or permit early stopping. Different crop counts have different update counts.
- Protocol version 11 supersedes v9/v10 per-epoch waveform resampling with one legal support crop pool per meta inner/refit CNN fit. Editable `support_pool_crops` defaults to 32 per event/class and must be at least the fixed per-epoch `support_crops` count (currently 4). Draw K pool slots without replacement per event/class each epoch; optional per-class caps apply afterward. Build a new pool each fit, encode it once, and never reuse its cached features after a frontend update. Preserve the full epochs, SGD update budget, continuous CNN/BN state, query policy and all role restrictions. Final-support loss weights slots by their actual use counts across epochs; unused slots have zero weight. Sum direct and inner-trajectory feature adjoints before one chunked frontend VJP, preserving full SGD/BN hypergradients. Replay waveforms from a private saved pool RNG state without advancing caller RNGs. Require a fresh v11 session/baseline for future training and preserve all older snapshots; this migration does not launch training.
- Protocol version 12 replaces v11 usage-count weighting with the uniform arithmetic mean over every support pool slot at the final CNN/BN state. Each slot counts once, including slots never selected by inner SGD; final support accuracy uses the same scope. Pool usage counts are diagnostic only. Keep support_loss_weight, query-event mouse weights, sampling, cached-feature/full-hypergradient semantics and all optimization settings unchanged. Report pool objective sample count separately from SGD draw count. Future training requires a fresh v12 session/baseline, preserving older immutable runs; editing does not launch training.
- Protocol version 13 changes training output only: readable per-mouse/outer-step summaries and periodic refit evaluation in train.log, complete detailed events in train.events.jsonl, and unchanged scientific metric artifacts/measurement frequency. Preserve RNG streams, optimization, full hypergradients, data roles, selection and v12 equal-pool support loss. Future training needs a fresh v13 session; do not hot-patch existing snapshots. A separate scripts/format_train_log.py live view may read old metric artifacts into train.readable.log without changing their source, original logs or execution. Logging edits do not launch or restart training.
- Do not fit dataset or task normalization statistics. Normalization inside the candidate may use only the current waveform and learned frontend parameters. The baseline uses sample-local RMS and GroupNorm; alternatives are allowed within that boundary.
- The only meta-parameters are the shared preprocessing frontend. Train a task-local CNN from reproducible unlearned starting weights for that candidate; CNN architecture/initialization may differ across candidates. Never meta-learn CNN initialization or carry adapted classifiers between tasks. Preserve the frontend-to-inner-training-to-query gradient path.
- Train the inner CNN for complete shuffled epochs, preserving weights and optimizer state within a task. `inner_shuffle_seed` remains locked; fixed shuffles must not advance the run's RNG streams. The solver implementations remain plain inner SGD without momentum and outer AdamW; their exposed rates/weight decay and classifier dropout are editable optimization parameters. Final per-mouse fitting uses the same inner solver and candidate parameters. Do not add optimizer selectors or moment tensors to the inner fit. `inner_weight_decay` adds a zero-centered L2 term after loss-gradient clipping, matching plain PyTorch SGD weight decay identically in meta inner and per-mouse fits.
- Train every inner CNN for exactly the candidate's configured complete epochs, with no early stopping or best-epoch rollback. Epoch/outer-step budgets may change only as explicit cross-candidate optimization hypotheses, never in response to intermediate metrics within a run. The version-13 baseline JSON uses 40 inner epochs rather than the Config default of 50, and the user-fixed 200 outer steps rather than the Config default of 100; retain these values until an explicit user-authorized budget change. Intermediate support metrics are diagnostic only. Preserve diagnostic frequency, the support-trained BatchNorm EMA, full eligible support/query tasks, and every data-role restriction. Do not recalibrate BatchNorm after fitting.
- The per-mouse outer objective is `query_loss + support_loss_weight * support_loss_after_last_update`. The support term averages all support pool crops with equal weights after the final inner update, including unused slots, in eval mode with the support-trained BatchNorm EMA, without dropout or statistics updates. Use configured label smoothing for both terms. Preserve direct frontend gradients and full hypergradients through every inner update and support statistics. The coefficient is editable, finite, and nonnegative; default 0.1 and zero restores query-only training. Apply the existing query-event mouse weights to the entire objective. Log query loss, final-support loss, weighted support term, and total separately. Query/valid checkpoint selection and development-test ranking remain unchanged.
- Use RNG-preserving activation checkpointing for long inner trajectories; do not silently truncate their hypergradients. Final per-mouse CNN fitting uses the same fixed epoch solver and budget.
- Final per-mouse fitting freezes the shared frontend and trains a fresh CNN from a reproducible unlearned reference.
- Restore normal CNN BatchNorm behavior: support training uses batch statistics and updates task-local running means/variances; query/test use eval mode and the fitted support statistics. Reset statistics with each fresh CNN and save the fitted statistics with adapted checkpoints. Checkpoint/replay must include the task-local BatchNorm state and preserve the full outer gradient through its support-only EMA updates. Never let query inference or backward replay mutate saved/reference statistics. Use PyTorch BatchNorm defaults: epsilon 1e-5 and momentum 0.1 meaning 10 percent new statistics per update; training normalizes with biased batch variance and saves unbiased running variance. After fitting, use the accumulated support EMA directly for final-support/query/valid/test inference. Never perform a separate recalibration pass or use query data for statistics.
- Select checkpoints by minimum mouse-mean log loss on the selection days after matched support-only CNN fitting (query days only when `selection_validation_days` is null, which selects the most query-fitted frontend). Report accuracy at threshold 0.5. Test metrics never select checkpoints within a training run; they rank completed frontend candidates only. Record sample counts, class ratios, window settings, source fingerprints, configuration, runtime, and selected checkpoints.
- Query loss and the final-support regularizer supply the outer gradient; selection days only select checkpoints. Query and selection never supply inner CNN updates or fitted normalization statistics. The outer optimizer is AdamW with decoupled `outer_weight_decay` on frontend weight matrices only (not biases, normalization parameters,).
- Score test Days 12/13 every eval_every steps (also the final step), alongside query metrics, without fitting or gradients. The separate test command replays selected checkpoints without training. Never use test metrics for within-run checkpoint selection.
- After each completed meta inner fit and per-mouse refit, score one fresh support crop draw and one fresh query crop draw when that role uses crops. Use the role's existing crops per event/class and caps; no additional CNN fitting, gradients, BatchNorm statistics updates, or checkpoint selection. Separate role-keyed diagnostic RNGs must preserve every caller training/query RNG stream. Log loss/accuracy and available fit-to-fresh gaps. New draws may overlap fitted windows; report them as within-day crop diagnostics, not independent-event/day validation. This user-requested change is protocol version 8; future training uses a fresh session/baseline and preserves version-7 artifacts.
- Source preparation verifies recording identities and annotation alignment. Describe signal-quality audits by their actual coverage.
- Keep dependencies stable in a comparison. Preserve source snapshots and completed/interrupted run records; resume only compatible checkpoints.
- Accept only current configuration and artifact fields. Do not add historical aliases, schema migrations, identity-scale parameters, or alternative training paths. Replay commands name one role: query, valid, or test.
- Preserve caller CPU/CUDA RNG streams during seeded initialization; instantiate each CNN once.
- Use English in code, comments, configurations, logs, and project documentation.
